# Phase 3d-1: VE Migration to SegmentHost Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Restore VE's inner driver to the original asynchronous VE2 structure, keeping the WorldVoice additions the user chose.
- Move the outer VE wrapper onto `SegmentHost` by queueing record-bound tasks on the inner `BgThread`.
- Fix C3 for VE and remove VE's contract 4 xfail.

**Architecture:**
- **Task 1** adds `SegmentHost.wait_idle()`.
- **Task 2** has two parts:
  - The inner `driver/VE/driver/__init__.py` returns to the original `BgThread` queue: queued `ProcessText2Speech`/`DoneSpeaking`/settings, the queue-scanning `getParameters`, and the original `cancel`/`terminate`. It keeps Sonic, the exponential rate/pitch mapping, the old Rate/Pitch/Volume commands, the install-path tweaks and the `_veCallbackHandler`/`_voice` fallback. `setDaemon(True)` becomes `self.daemon = True`.
  - The outer `driver/VE/__init__.py` submits each record as `Begin` → per-piece `NativeTask` → inner `DoneSpeaking` → `Retire` on that queue.
- The `BgThread` is the FIFO worker.
- `speak()` and `speak_segment()` both return once queued.
- `cancel()` drops queued speech but keeps settings and the ordinary DONE, and never joins the `BgThread`.
- A closer finishes termination.
- Cerence and every other engine are untouched.

**Tech Stack:** Python 3 threading, ctypes, pytest, ruff.

**Spec:** `docs/superpowers/specs/2026-10-03-phase3d1-ve-design.md`

## Review Focus

1. **Deadlock-freedom of `cancel()`/`terminate()` re-entry.** VE now has five actors: the scheduler, the inner `BgThread`, native callbacks, lifecycle threads and the delivery thread.
   - `cancel()` never joins the `BgThread`.
   - `terminate()` re-entered from the `BgThread`, a callback, a player operation or the closer starts a closer thread instead of waiting.
   - The closer joins the `BgThread` and waits for `host.wait_idle()`.
   - Covered by the existing tests:
     - `test_ve_shared_player_hook_can_reenter_terminate`
     - `test_done_listener_can_terminate_without_deadlocking_speech`
     - `test_index_listener_can_terminate_and_retire_native_before_close`
     - `test_reentrant_player_terminate_waits_for_own_operation`
     - `test_terminate_waits_for_pause_fault_stop_without_active_speech`
     - mutation M2h.
   - The reviewer should look for a path where the closer, run on a lifecycle or delivery thread, joins a `BgThread` that is waiting on that same thread.
2. **Queue surgery in `cancel()`.** `_drop_queued_speech` must keep `TtsSetParamList` entries, the `Retire` of the record whose `Begin` already ran, and the ordinary `DoneSpeaking`. It must drop queued `Begin` entries (and abandon those records) and drop segment `DoneSpeaking` entries. A kept `NativeTask` is a no-op.
   - Covered by `test_cancel_during_contextual_final_idle_releases_waiting_ordinary` and `test_ve_cancel_drops_a_segment_queued_behind_the_worker` (M2b, M2c).
   - Check the race where the `BgThread` has popped a `Begin` that has not run yet.
3. **The approved behavior changes**, which apply to ordinary VE speech only:
   - Asynchronous `speak()` (`test_ve_speak_returns_before_native_synthesis`, M2e).
   - Queued settings (`test_ve_settings_apply_in_call_order_with_speech`, M2d).
   - Native errors are no longer raised to the `speak()` caller.
   - `cancel()` drops ordinary speech queued behind a segment.
   - The reviewer checks that nothing else in WorldVoice relied on VE's synchronous `speak()` return or on errors raised from it. `compat/engineAdapter.py` and LEGACY_DONE completion wait for DONE events, not for `speak()` to return.
4. **Inner fidelity.** Diff the inner driver against `ref/VE2-min`. Every difference must be one of the kept items or `self.daemon = True`. The ordinary DONE after cancel follows the original.
5. **Settings applied outside the queue.** `Voice.applyEngineSettings` still applies the variant immediately via `TtsSetParamList(...)()` on the scheduler thread. This is safe only because the scheduler applies settings after the previous segment drained. The reviewer checks that no path applies it while the `BgThread` synthesizes.
